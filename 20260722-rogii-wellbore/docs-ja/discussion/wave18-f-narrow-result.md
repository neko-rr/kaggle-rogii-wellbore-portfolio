> 目的: 「F で閉じた理由でも、井戸の傾向で範囲を狭めれば有効では？」への **実証回答**  
> 提出: **なし**

## 1 行結論

**ほぼ蘇らない。** 狭めて効く候補は、すでに Wave-13/14/17 で実装済みの  
`portable × tip_std（farvol / two-stage）` に吸収されている。  
F012/F018 など「別面」系は、狭めるほど適用が減るか、狭帯でも tip に負けたまま。

---

## なぜ「狭めれば」と聞きたくなるか

優秀な Kaggler の直感として正しいのは次の区別:

| 失敗の型 | 狭めで救済できるか |
|---|---|
| **適用範囲が広すぎた**（sample を巻き込んだ） | **できる** → ゲート化 |
| **機構そのものが弱い / 信号が無い** | **できない** → 井を減らしても無駄 |
| **前提条件（密度・別面）が欠ける** | **狭めると悪化** |

自チームの F の大半は後者2つ。

heel 低 × tip_std 高（farvol 帯）でも CF wins = 0。

### CHK-200（F012 狭帯）

- gated_used: **3/20**（密度不足は再確認）
- 通過井でも tip − neighbor Δ 平均 **−27**（近傍の方が悪い）
- → 「もっと厳しくする」と適用が消えるだけ

### CHK-199 / Type A

- Type A = `tip_std < 0.842` 上の portable → **farvol 除外と同一**（Δpool≈+0.072）
- **新規レバーではない**（ALREADY_COVERED）

### CHK-195r（F015 の「信号だけ」利用）

- SOFT 移動量大 × tip_std 低だけで apply
- 最良 Δpool **+0.057**（strict PASS）だが portable（+0.053）を **明確に超えず** → **NO-GO**
- 中間面の **提出昇格は引き続き禁止**

## では何が「狭い適用で有効」だったか

すでに持っているものだけが答え:

1. **`self_dev` × `heel_corr` portable ゲート**（弱い SOFT）  
2. **`tip_std_far/prox` で B 型除外 / two-stage 半減**  
3. **sample 井は tip FINAL を触らない**（Wave-14×186）

これは F020 の「攻撃的全井」を狭めた成功例であり、F011–F019 の復活ではない。
