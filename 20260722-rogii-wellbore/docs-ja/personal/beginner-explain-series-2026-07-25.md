## 1. 多切り口診断は何を想定していたか

### 一言でいうと

今回の「多切り口診断」は、**新しい予測モデルを作る話ではない。**  
すでに出ている tip（今の主予測）に対して、**あとから少しだけ直す「後処理」**を、どの井にどう掛けると得か／損かを見た。

想定していた後処理は、Wave-11〜13 で扱ってきた **「弱い tip 自己線ブレンド（SOFT / gated SOFT）」**。

### その後処理は何をするか

水平坑井の評価区間では、tip が「この先の TVT」を予測している。

SOFT 後処理のイメージ:

1. 井の **手前側（近MD）** の tip の並びから、だいたいの直線（自己線）を引く
2. **奥側（遠MD）** だけ、tip の値をその直線のほうへ **少しだけ寄せる**
3. 寄せ方の強さは弱め（例: strength **0.05〜0.08**）・遠方の範囲も抑えめ（例: far **0.33**）

「全部作り直す」のではなく、**遠方が線から外れすぎているときだけ、そっと戻す**処理。

### なぜ「多切り口」で診断したか

この後処理は **すべての井に効くわけではない。**

| 井のタイプ（ざっくり） | 後処理をすると |
|---|---|
| 遠方が「変なドリフト」で線から外れている | **効きやすい（A：助け型）** |
| 遠方のジグザグが本物の形っぽい | **逆に悪化（B：悪化型）** |
| もともと簡単な井 | **触らない方がよい**（全体 SOFT は sample を壊しやすい） |

診断で使った切り口の例:

- 遠方がどれだけ線から外れているか（`self_dev`）
- tip の形（遠方のブレ ÷ 近傍のブレ = `tip_std_far/prox`）
- 方位・heel整合・hard/sample など

想定していた操作は一貫して:

- **掛ける / 掛けない（ゲート）**
- **弱く寄せる（strength・far）**
- **悪化しそうな井だけ除外する**

CF への置き換え・近傍コピー・新しい学習モデルなどは **想定していない**（既に禁止・失敗済み）。

### 診断の結論を後処理の言葉で言うと

1. **全井に SOFT** → ダメ寄り（簡単な井まで傷つく）
2. **難しい井だけ弱い SOFT（gated）** → 有望（Wave-13 portable）
3. その中でも **遠方が相対的にジグザグな井** は SOFT を **掛けない**方がよい（A/B 分離の本命）

つまり「多切り口診断」＝ **「この後処理を、誰に・どれだけ・いつ止めるか」を決めるための地図作り**。

## 2. 他に後処理の方法はあるか

**ある。ただしこのコンペでは、「やってよい後処理」はかなり絞られている。**

### いま主に想定しているもの（継続中）

**弱い tip 自己線ブレンド（SOFT）＋井ゲート**  
遠方だけ直線へ少し寄せる。Wave-13/14 の本線。

追加の切り方として有望なのは:

- **掛ける井を選ぶ**（`self_dev`・heel）
- **悪化しそうな井は掛けない**（`tip_std_far/prox`）
- strength / far を弱く保つ

### 後処理の「種類」としては他にもある

| 系統 | 何をするか | このチームでの扱い |
|---|---|---|
| **ブレンド** | tip と別予測を混ぜる | tip×Best は **F016** で閉鎖（同じ最終面） |
| **区間の寄せ** | 遠MDだけ別ルール | 自己線 SOFT がこれ · 攻撃的は **F020** |
| **フォールバック** | 条件付きで CF 等に切替 | 低整合→CF は **F018** で壊滅 |
| **直線・外挿** | heel から遠方を引く | **F019** で壊滅 |
| **方位・セグメント別** | NW_N だけ強く直す | **F006/F009/F014** で禁止寄り |
| **平滑化** | ジグザグをならす | 未本命 · tip 形を壊しやすい |
| **クリップ** | 異常値を上下限で切る | 補助にはなり得るが本命ではない |
| **中間成果物の採用** | mpkg 等を最終にする | **F015** で Public 悪化 |

「方法のカタログ」はあるが、**スコア用に残っている合法レバーはほぼ「弱い gated SOFT の掛け分け」だけ**。

### まだ「薄い・未確定」で検討余地があるもの

提出の主軸にはまだしない前提:

1. **SOFT の掛け方の微調整**（いまの延長）— farvol 除外の本採点（CHK-184）など
2. **ごく弱い平滑化**（遠方だけ）— 未検証 · tip 形を壊すリスク大
3. **異常値クリップ** — 大改善は期待しにくい
4. **何もしない** — easy 井・B型は「後処理しない」も立派な戦略

### まとめ

- 他の後処理方法は一般にはある
- 似たことはすでに試して **失敗台帳（F006〜F020）で閉じたものが多い**
- 今いちばん筋がいいのは **「tip を大きく作り直さない · 遠方を弱く直す · 井を選ぶ」**

## 3. いまのモデルは何か · 各工程で何を試せるか

### いまの「モデル」は何か

主に使っているのは、公開 Notebook 由来の **tip**（`rogii-luck-is-all-you-need` 系）。

「1個のニューラルネット」ではなく、**何段もの処理を直列につないだパイプライン**。家系は **Contact-Gated（層の当たりを合わせて TVT を出す）同族**で、Public Best も同じ系統。

```text
データ（水平井GR・Typewell・軌道…）
    ↓
① 粗い位置合わせ（ridge / PF など）
    ↓
② 投影・公開部品のブレンド
    ↓
③ Contact ガード（変な合わせを抑える）
    ↓
④ VP 校正
    ↓
⑤ model-package（小さな補正パッケージ）
    ↓
⑥ 分岐 hedge（BH・多シードの中点など）
    ↓
【tip 最終予測】← いまの「本体の答え」
    ↓
⑦（実験中）弱い SOFT 後処理 ← Wave-11〜14 はここ
    ↓
submission.csv
```

既定プロファイルはだいたい **`vp_balanced_modelpkg_005`**（二峰検出OFF・package ON）。

### 各工程で「何を試せるか」／すでに閉じたか

| 工程 | やっていること（初学者向け） | 試せそうなこと | このチームの実情 |
|---|---|---|---|
| **① PF / 位置合わせ** | GR と Typewell をずらして「どこが対応するか」を探す | ノイズ尺度・シード・窓 | `gs×1.3` は **もう tip 内**。乱獲は禁止帯 |
| **② 公開ブレンド** | 複数公開部品を混ぜる | 重み | 同家系の寄せ集めになりやすい |
| **③ Contact ガード** | 変な接触補正を抑える | ON/OFF・強さ | 安全側の設計。OFF は危険 |
| **④ VP 校正** | プロファイルを整える | プロファイル切替 | F013 で梯子いじりは失敗寄り |
| **⑤ model-package** | 小さな学習済み補正 | 重み・採用面 | **中間面を最終にするのは F015 で悪化** |
| **⑥ BH / 分岐 hedge** | 二峰・分岐の保険 | strength・sep | 後処理 BH↑は F006/F009 · 決め打ちも弱い |
| **⑦ SOFT 後処理** | 遠方を自己線へ弱く寄せる | ゲート・除外・弱さ | **いま残っている主な改善口** |

「本体を別モデルに差し替える」（近傍転写・NCC+木・DTW・方位分割学習など）は、実験の結果 **ほぼ閉鎖（F011〜F017 など）**。

### 後処理の結果から見える「本体」の弱点

1. **簡単な井** — tip はもう十分よい → 触ると悪化しやすい
2. **遠方が「線から外れたドリフト」の井（A）** — 弱い自己線寄せが効く → 本体の弱点は「遠MDの低周波ドリフト」
3. **遠方がジグザグな井（B）** — 直線で潰すと悪化 → 「寄せすぎ」が問題

後処理が教える改善方向:

- **遠方ドリフト型だけ補正する**（選択的）
- **形が本物っぽい遠方は壊さない**

「全体をもっと強く直線に寄せる学習」ではない。

### モデル本体の改善方向は「あるか」

**現実的に残っているもの（締切近・推奨）**

| 方向 | 内容 | 期待 |
|---|---|---|
| **A. 最終面を守ったままの選択的補正** | gated SOFT + `tip_std_far/prox` 除外（CHK-184） | いちばん筋がよい |
| **B. Final 運用** | 枠1=Trust tip · 枠2=Public Best | 必須（守り） |
| **C. tip 内部の極小ノブ** | 既にある安全側設定の固定・再現 | 大伸びは期待しにくい |

**理論上あるが、今は期待値が低い／禁止寄り**

| 方向 | なぜ今は切るか |
|---|---|
| 新しい照合・近傍・DTW で「別の予測面」 | F011/F012/F017 などで同面か壊滅 |
| tip の中間出力を最終にする | F015 で Public 悪化 |
| 方位で学習を分割／BH を強く | F014 / F006/F009 |
| 行ごとの木モデルで残差学習 | F010 など · tip に吸い込まれやすい |
| 二峰を分類してモードを決める | EDA上、平均に負けやすい |

**率直な結論:** 「本体アーキテクチャを大きく変えて伸びる」余地は、この時点では **かなり小さい**。残るのは **最終 tip 面を壊さない選択的後処理** と **Final 2枠の運用**。

### まとめ

- いまのモデル = **Contact-Gated 系の多段パイプライン（tip）**（1個のNNではない）
- 工程①〜⑥が「本体」、⑦が「後処理」
- 本体の大胆な作り直しは、すでに多く失敗して閉じた
- 次に効きやすいのは **「どの井の遠方だけ、弱く直す／直さない」**

## 4. Public 4.859 と 6.0 帯の差 · Private シェイク

> 数値は会話時点の Public LB 読み（詳細は [`leaderboard.md`](../leaderboard.md)）。自 Best の正は `exp-index`。

### まず数字の意味

RMSE は **低いほど良い**。

| 帯 | Public 目安 | 意味 |
|---|---|---|
| **1位** | **4.859** | いまの山頂 |
| **だいたい30位前後** | **≈6.0** | 上位グループの入り口付近 |
| **自分（Best）** | **≈6.52** | Contact-Gated 同族の「良い公開解」帯 |
| **公開フォークの密集帯** | **6.5〜7.5** | 同じ系統の人がたくさんいる沼 |

1位と「6.0帯」の差は約 **1.1**、自分との差は約 **1.6**。  
seed の揺らぎ（0.05〜0.3）より **ずっと大きい**ので、「たまたま1回うまくいった」だけでは説明しにくい。

### 自分（≈6.5）と1位（4.859）に考えられる違い

確定ではない。「ありそうな差」として読む。

1. **予測の“面”が違う（いちばん大きい）**  
   自分側は Contact-Gated 同家系。1位付近は同家系の極限チューニングか、**別系統の強い成分**の可能性がある。後処理だけで 6.5→4.8 は自チーム実績から見て非現実的。

2. **Public 26% への当たり方（過学習）**  
   Public はテストの約26%だけ。そのスライス特化だとスコアだけ飛ぶ。

3. **データ・外部知見・本体内の条件分岐**（Rules 準拠の範囲での推測）  
   リーク疑いは差の説明に使わず、疑うだけにする。

4. **自分側ですでに閉じた道**  
   別予測面は失敗か同面が多かった → 差は「まだ持っていない強い面」か「Public特化」かその両方。

### Private ではどう変わりそうか

- 今見える順位 = テストの **約26%**
- 最終順位 = 残りの **約74%**

| シナリオ | Private で起きやすいこと |
|---|---|
| 1位が本当に全体で強い | Private も強く、上位に残る |
| 1位が Public 特化 | Private で **大きく沈む（シェイク）** |
| 6.0〜6.5 の同族密集 | Private でも **まとまって共沈／共浮き**しやすい |

自分の帯（6.5前後）は「公開 Contact-Gated 沼」なので、Private でも **金メダル帯へ一気に跳ねる**より、**銅〜銀の争いで入れ替わる**イメージの方が現実的。

### 「差が大きいなら、シェイクしても1位は上位か？」

**「絶対に上位」とは言えない。**

| Public差 | シェイク耐性の読み |
|---|---|
| 0.05〜0.2 | ほぼノイズ。順位はすぐ入れ替わる |
| 0.3〜0.7 | 揺れるが「系統の差」になりやすい |
| **≈1.0以上（今回）** | 本物なら強い。ただし **Public過学習なら大転落もありうる** |

優秀な読み方:

1. 1位を「確実な優勝者」と思わない（Private 74% が本番）
2. かといって自分（6.5）がすぐ4.8に追いつくとも思わない
3. 枠1=Trust CV tip · 枠2=Public 最良 · Public 追いの乱打はしない

### まとめ

- 自分と1位の差は **「同じ公開解の微差」より大きい**
- 違いはおそらく **モデルの強さ／別系統／Public特化** の混合
- 軽いシェイクだけでは1位が30位付近まで落ちるとは限らないが、大シェイクなら落ちうる
- 現実的目標は、1位を真似て4.8を狙うより **同族帯での安定（銅〜銀）と Final 2枠運用**

## 5. おまけ: A/B（助け型・悪化型）を分ける手がかり

> 詳細の正: [`wave14-well-archetypes-2026-07-25.md`](../wave14-well-archetypes-2026-07-25.md)

**問題:** `self_dev`（遠方が線からどれだけ外れているか）が高い井の中に、SOFT で助かる井（A）と悪化する井（B）が同居する。`self_dev` だけでは分けられない。

**たとえ:** 「線から外れている」ことまでは分かるが、「変なドリフト」か「本物のジグザグ」かは、外れ量だけでは分からない。

**本命の手がかり（Wave-14）:**

- **`tip_std_far / tip_std_prox`**（遠方のブレ ÷ 近傍のブレ）
- 遠方が相対的にジグザグ（この比が大きい）→ **悪化型 B 寄り** → SOFT を掛けない方がよい
- 遠方が相対的に静か → **助け型 A 寄り** → 弱い gated SOFT が効きやすい

方位だけの代理除外は過除外で NO-GO。shape 特徴の本採点は **CHK-184**（Public 後・承認後）。

## 6. ボトルネックは選択ではなく generator 不足

> 根拠: CHK-185（[`chk185-candidate-ceiling-result.md`](../discussion/chk185-candidate-ceiling-result.md)）

### 一言でいうと

いま手元にある「答えの候補」の中から一番いいものを選んでも、まだ点数が足りない。  
つまり問題は「選び方が下手」ではなく、**そもそも候補の中に、十分良い答えが入っていない**こと。

### たとえ話

テストで「答えの候補」が紙に何枚か書いてあるとする。

| 役割 | たとえ | このコンペでの意味 |
|---|---|---|
| **generator（生成）** | 候補の紙を作る人 | tip / PF などが「ありそうな TVT の道筋」をたくさん出す |
| **scorer / 選択** | どの紙を最終答案にするか決める人 | その中から1本を選ぶ（SOFT の掛け方なども含む） |

Discussion ではこう言われていた。

- 「良い候補はだいたい **4.5 くらい**まで存在する」
- 「難しいのは **どれを選ぶか**」

でも CHK-185 で、ディスク上の tip 家系を測るとこうだった。

### 手元で起きたこと

1. **選び直してもほとんど伸びない**  
   tip と SOFT など、すでに持っている候補を、ラベルを見て一番良いものに差し替えても  
   全体で **8.33 → 8.18（約 +0.15）** しか良くならない。

2. **ほとんどの井では、すでに tip が一番良い**  
   80井のうち **64井**は、候補の中で tip が最良。  
   →「選び直せば伸びる」余地がほとんどない。

3. **それでも悪い井は悪い**  
   一番良い候補を選んでも、**23井はまだ RMSE > 6**（難井は 10 超えも多い）。  
   → 候補の中に「良い答え」自体が無い。

| 言葉 | 意味 |
|---|---|
| **選択がボトルネック** | 良い候補はある。選び方を直せば伸びる |
| **generator がボトルネック** | 良い候補が無い。選び方を直しても天井が低い ← **今回はこちら** |

### なぜ「1位 4.859」と差が大きいか

1位付近は、おそらく次のどちらか（または両方）。

- **もっと良い候補を最初から出せる generator** を持っている
- あるいは Public の一部にだけ極端に合う作り（別問題）

いまの tip+SOFT の机の上には、**4.8 帯の答案が入っていない**。  
後処理で「どれを掛けるか」を工夫しても、机に無い答案は出せない。

### まとめ

| やりたいこと | 実体 |
|---|---|
| 選択を直す | 机の上の紙から選ぶ |
| generator を直す | **机に載せる候補そのものを良くする** |
| いまの SOFT 改良 | 候補を増やさない。机の上の紙を少し直すだけ |
| 次の現実的打ち手 | Final 2枠を固める · CHK-184 は +0.15 級の任意 · 閉じた別面は再掘りしない |

## 7. もっと良い候補を出せる generator をどう改良するか

### 一言でいうと

「良い generator」＝**最終答案を選ぶ前に、机の上に近い答えの候補を置く能力**。  
改良は「後処理をもっと工夫する」ではなく、**候補を作る本体（照合・粒子・パス生成）を良くする**側の話。

### generator が何をしているか

1. 水平井の GR と Typewell を見ながら  
2. 「この TVT の道筋がありそう」という候補をたくさん作り  
3. そのあと scorer（尤度・重み）で1本に絞る  

tip（Contact-Gated）は、その **1〜3 をまとめた公開パイプライン**。  
SOFT は③のあと遠方を少し直すだけで、**①②の候補そのものは増やさない**。

| 改良の種類 | 意味 |
|---|---|
| **A. 当たり候補を出す確率を上げる** | 真の道筋が粒子／候補に入る割合を上げる（hengck の generator）← **いま主に必要** |
| **B. 尤度で正しく順位付けする** | 良い候補があっても誤った道を選ばない（scorer）※CHK-185では B の余地は小さい |
| **C. 別の候補源を足す** | 近傍コピー・別物理・別 NN など ※多くは F で閉鎖済み |

### 期待値が残る／議論と整合するもの

1. **tip 内部の「粒子・シードが真値に近いか」を測る（診断）**  
   - Discussion: 「まず generator の命中率を測れ」  
   - tip が粒子ログを出せるなら、CHK-185 の次は「SOFT ではなく PF 候補」の天井  
   - **まだやっていない本命診断**（CHK-186 想定）

2. **尤度／ノイズ／窓など、tip がすでに持つ安全ノブの再校正（小）**  
   - `gs`×1.3 は既に tip 内。大胆な切替は F013 で失敗済み  
   - 大伸びは期待しにくい

3. **Final 2枠でリスク分散（運用）**  
   - 枠1=安定 tip · 枠2=Public Best  
   - generator を短期間で 4.8 まで上げるのは難しいときの正しい守り

### 期待値は低い／禁止寄り（やらない）

| やり方 | 理由 |
|---|---|
| 近傍&lt;150ft コピーを再実装 | F012 |
| 方位分割学習の再実行 | F014 |
| NCC+木・整合ドリフト学習 | F011/F010 |
| 制約 DTW・heel 直線・CF フォールバック | F017/F019/F018 |
| tip×Best アービター | F016・同面 |
| 「学習 ranker で選べば 4.5」 | 手元に 4.5 候補が無い。Georgy も漏洩警告 |

「上位が持っている良い generator」を、**閉じた道の言い換えで真似る**のは最悪手。

### 推奨順（締切近）

```text
①（任意）tip の PF/粒子に真値が入るか測る
        ↓ 入らない井が多い
② generator 本改修は「高コスト・低再現」と認める
        ↓
③ Final2 を最優先で固める
        ↓
④ CHK-184 など SOFT は +0.15 級の任意のみ
```

- **①で「粒子には当たっているが最終が外れている」** → 初めて選択・scorer 側に戻る意味がある  
- **①で「粒子にも当たっていない」** → 短期間で 4.8 はほぼ無理 · Final 運用が正解  

CHK-185 は SOFT 集合だけを見たので、**PF 内部までは未計測**。
